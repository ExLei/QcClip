# 跨设备同步实现方案

## 产品边界

LAN 与 WebDAV 是同级、独立启停的通道，共用设备身份和信任。默认发送优先 LAN；LAN 不可用或失败时，可使用已启用的 WebDAV。明确的“上传当前内容到 WebDAV”跳过 LAN。

同步只处理启用之后新增的事件，以及用户手动选择的条目。不维护各设备完整历史的一致性，不传播本地删除，不需要管理完整云端数据集的增删改。接收内容进入 QcClip，默认同时写入系统剪贴板，可在同步主页关闭“接收后写入系统剪贴板”。

LAN 使用在线会话、90 秒消息有效期及入库确认；WebDAV 使用有界异步缓存，不维护在线租约或会话，不在接收后删除缓存，不轮询入库回执。两者分别处理在线帧和缓存条目，共用内容校验与入库规则。开发期协议不做兼容迁移；已发布数据库 schema 1 升级到 schema 2 的迁移继续保留。

LAN 会话只保存在内存，启动或配置变更时重新生成；设备身份和发送序号持久保存。开发阶段旧字段不建立迁移链。

## 身份、配对与加密

- 每台设备独立生成设备 ID 和 X25519 公私钥，两种通道共用已配对目标。
- 同网通过 UDP 发现、6 位随机码的 SPAKE2 认证及接收方人工确认配对。发现窗口 5 分钟，请求 3 分钟，每个请求最多 3 次验证尝试，每个搜索窗口最多接收 6 个新请求。UDP 发现固定使用 39827 端口，TCP 直连默认使用 39827，可单独调整。
- 远程添加使用同一 WebDAV 目录交换加密身份，16 字符临时配对码 5 分钟有效，双方分别核对确认；完整设备码是备用方式。
- 内容使用 crypto_box SalsaBox（X25519 + XSalsa20-Poly1305），随机 24 字节 nonce。每个目标独立加密，没有所有设备共享的长期内容密码。
- 在线消息、缓存条目、缓存资源采用不同的认证用途，防止缓存消息冒充在线帧；版本、双方身份、时间和用途位于认证密文内。
- Windows 身份与 WebDAV 凭据由 DPAPI 保护，保存在 `%LOCALAPPDATA%/QcClipDevice/sync.bin`，不使用 Windows 凭据管理器，不随内容导入覆盖。其他平台尚未提供安全身份存储。
- 当前使用长期设备密钥，无前向保密。撤销拒绝后续本机收发，不撤回对方已收到或此前获准访问的缓存内容。

## WebDAV 存储与索引

应用在配置的已存在目录下创建 `qcclip-v1/indexes/`、`qcclip-v1/objects/`；远程配对另用 `pairing/`。

每台发送设备维护一份索引，地址由设备公钥派生。接收方根据已有信任直接定位索引，不需要发现目录或读取总索引。索引内的每次目标投递是单独认证加密的条目，其他目标无法解密。随机资源标识和派生路径不包含内容、文件名或原始内容哈希；服务端仍可观察时间、尺寸和访问关联。

- 原始资源总量不超过 16 KiB 的条目内嵌索引，上传稳定状态为一次 PUT，拉取新内容不再额外 GET 正文。
- 大内容将本条目的所有资源组成一个加密对象，一次 PUT 对象后再 PUT 索引，不再按每个 256 KiB 分片分别请求 WebDAV。
- 索引最多 4 MiB。容量同时限制投递条数和原始资源总字节；默认 100 次目标投递、100 MiB，分别可配置为 1–1000、1–1024 MiB。向多个目标投递分别计数。编码、加密与元数据产生的实际服务端空间开销不计入原始容量。
- 达到条数、原始容量或索引上限时，按实际上传顺序淘汰最早投递。上传旧历史记录也算一次新投递，不按条目的原始捕获时间淘汰。
- 接收不会删除缓存，其他目标仍可取件。长期未拉取的设备可能错过已经淘汰的内容，不从完整历史补齐。
- 上传提交标志是索引 PUT 成功。UI 表示“已上传，对方可稍后拉取”，不表示对方已入库，不查询 ack。

发送端串行更新自己的索引，避免本机文本与资源工作线程覆盖对方的发布结果。首次上传读取自己的权威索引，后续在内存副本上更新；重启或发布响应异常后重新读取。禁止把同一身份文件复制给多个应用实例作为不同设备使用。

## 容量淘汰与失败恢复

先上传资源，再发布新索引，最后删除淘汰的资源。不提前删除旧索引仍引用的内容。删除路径限定在本设备的对象前缀，且对象标识必须是 UUID。

发布前将新对象和待淘汰对象写入本地原子清理日志。若上传中断、索引响应丢失或应用退出，下一次上传先读取云端权威索引，只删除未被引用的日志对象。已经提交但响应失败的内容不会被误删。清理失败不把已成功发布的条目误报为上传失败；下次上传继续清理。

清理日志仅含随机对象标识，不含密码或剪贴板正文。手动模式不为清理单独轮询，失败遗留对象可能保留至下一次上传。正在读取的旧快照也可能遇到容量淘汰；此时报告资源缺失，下一次重新拉取，不发布半成品。

## 自动与手动收发

- 自动上传与自动拉取独立开关。开启自动上传后，每次符合设备策略的本地新增立即进入上传队列，不等待多条合并。
- 手动上传只处理指定条目；关闭自动上传仍可操作。普通发送优先 LAN；明确的 WebDAV 上传始终使用云端缓存。
- 手动发送使用明确的历史或收藏类型，由右键菜单所在列表决定接收去向。标题栏上传最近一次本机复制/新增历史或新增收藏；本机操作在原写事务内记录，重启保留，远程接收不改写此记录。悬停显示类型和内容摘要。
- 自动拉取与手动拉取共用索引解析、资源校验和入库路径，手动拉取顺延下一次自动检查。
- 自动拉取默认 60 秒；提供节省请求（60 秒）、快速同步（2 秒）、手动拉取预设，支持自定义 1–86400 秒。没有坚果云专用硬速率限制。
- 同一轮拉取互斥，不叠加未完成的索引检查。文本和大资源接收分别使用有界队列；下载资源不占用唯一的索引检查线程。
- 关闭自动拉取时，正常空闲期间无 WebDAV 检查、心跳或在线状态维护请求。用户发起的配对、测试、上传和手动拉取独立执行。
- 配置变更、撤销或数据切换取消旧代次任务，资源提交前重新核验信任和通道状态。

## 请求预算与限流

协议减少无效请求；间隔由用户选择，不能把限额服务的上限套用到自建服务。

| 稳定运行场景 | 请求数 |
| --- | --- |
| 空闲检查一个已配对发送设备 | 1 次 GET 索引 |
| 小内容上传至一个目标 | 1 次 PUT 索引 |
| 大内容上传至一个目标 | 1 次 PUT 资源 + 1 次 PUT 索引 |
| 拉取索引中尚未处理的小内容 | 包含在索引 GET 中 |
| 拉取尚未处理的大内容 | 每个条目额外 1 次 GET 资源 |
| 手动模式正常闲置 | 0 次 |

初始化、首次上传读取自己的索引、容量淘汰 DELETE、配对、测试与失败重试额外计数。目录初始化与 HTTP 客户端跨操作复用；常规拉取无 MKCOL、PROPFIND、PUT 租约、GET ack 或 DELETE。

以用户提供的坚果云 600 次 / 滚动 30 分钟、所有设备共用额度估算，N 台设备使用相同间隔 T 秒互查的空闲成本为 `1800 / T × N × (N−1)`。两台设备 60 秒为约 60 次，2 秒为约 1800 次。UI 显示本机实际近 30 分钟请求计数及本机空闲检查估算，不冒充账号账单或剩余额度。

429 / 503 根据 Retry-After（秒数或 HTTP 日期）设置共享冷却，没有该字段时默认 60 秒；冷却期间所有收发操作均不继续发请求。自动检查连续失败指数退避，成功后恢复用户间隔。没有请求预算硬上限；高速自建服务仍可每秒检查。

## 接收、去重与内容策略

缓存事件不依赖当前在线会话，也不使用 90 秒过期规则。每条仍绑定来源、目标、条目 UUID、状态流和持久递增序号。接收端在下载大资源前查询数据库中的每条目、每状态流水位；重启后不重复下载或入库，已删除的本地条目也不会因为反复拉取同一旧事件而复活。

所有资源在入库前校验身份、长度和 SHA-256，并再次核对当前配置代次。已有入库事务、来源身份映射及每条目/状态流的持久水位复用于 LAN 与 WebDAV，两通道重复到达只应用一次。

索引外层格式错误只影响对应发送设备，仍继续检查其他设备；索引内逐条解析、解密和校验，单条错误不阻塞其他内容。未知消息类型、缺失字段、密文损坏和资源不一致分别报告，异常条目不写入已接收水位，可在更新版本或重新上传后重试。

自动范围为新增历史、收藏新增和可选重复触达；不追溯同步既有历史，不自动发送已有条目的内容编辑。手动内容更新保留未发送格式，目标存在本地修改时拒绝覆盖。手动入口仅提供普通发送和 WebDAV 上传。

历史和收藏的内容事件均携带标签、备注，重复触达事件不携带。接收时补充对应列表关系；缺失标签自动创建，同名标签复用，接收方已有标签保留。备注仅在接收方为空时填入，不同备注保留本机版本并发出通知。空标签或备注不清除接收方数据，不传播取消收藏、删除、置顶或排序。

内容事件携带来源应用名称，不发送应用路径或图标。名称随现有事件端到端加密，不新增网络请求。接收端将来源应用及可信配对资料中的发送设备名称快照保存在 `sync_sources`，供历史和收藏共享；设备身份沿用已认证发送者。同步来源统一显示内置 QcClip 图标，提示“应用名称 · 来自设备”，应用名称缺失时仅显示设备。本机捕获来源优先；转发保留应用名称，设备表示本次发送方，不追溯最初设备。

格式筛选按 FormatRole，默认兼容优先，支持文本、富文本、图片及可保存的自定义原始格式。Internal、失败、虚拟文件和超限资源不发送；文件路径与实际文件内容分别控制，默认关闭。单事件原始资源上限 256 MiB，文件和图片另有设备策略上限。跨平台格式转换只在实际粘贴阶段处理。

实际文件接收至数据目录下 `data/sync-files`，保存相对路径、长度和哈希；迁移后重建本地路径并校验文件。不接受目录、符号链接或读取过程中改变的文件。无数据库引用的接收目录超过十分钟后回收，本地后台清理不产生 WebDAV 请求。

## 接收后的界面更新

`copy_on_receive` 为本机同步配置，默认开启，旧身份文件缺少字段时也按开启读取。局域网和 WebDAV 共用串行接收入库与写回入口，事务提交后复用 `PasteService::copy_item` 恢复原始格式；使用与剪贴板监听相同的写入抑制器，防止本机重复捕获及同步回环。历史和收藏均适用，不自动模拟粘贴按键、不增加粘贴统计。批量接收保留最后完成接收的内容；重复回执与同一发送设备迟到的旧内容事件不写回。写入失败仅发出全局错误通知，不撤销入库或要求重新投递。

入库事务返回实际受影响的内容 ID、历史关系、收藏关系和标签变动。重复回执不产生列表变更。后台合并待更新条目后通知 UI，状态通知与数据通知共用唤醒信号，但不会相互覆盖待处理内容。

主窗口只查询当前列表受影响的行及排序快照，不重载无关列表，不重新加载其他行正文。保留滚动位置、选中、多选和未变行的缓存；新标签补入标签栏。页面加载、分页和拖动排序期间延后应用；查询代次、页签、列表顺序或标签代次改变时合并重查，避免旧结果覆盖当前交互。

## UI 与维护入口

同步主页保留身份、设备与连接摘要，提供“拉取新内容”和本机请求统计。添加、连接、设备策略使用独立侧边抽屉，不嵌套；连接抽屉展示自动收发开关、拉取预设、自定义间隔、缓存上限和请求估算。启用 WebDAV 后，主窗口标题栏显示紧邻的横向上传、拉取按钮。手动操作结果和备注冲突接入全局通知，常规后台收发更新状态。

身份与凭据见 `services/sync/config.rs`，在线协议见 `protocol.rs`、`lan.rs`，配对见 `local_pairing.rs`、`pairing.rs`；WebDAV 传输与缓存分别见 `webdav.rs`、`dav_cache.rs`，任务编排见 `runtime.rs`，入库与去重见 `repository.rs`。本机最近操作由 `activity.rs` 和数据库写事务记录，列表局部更新见 `windows/main/state/sync.rs`。

稳定的回归入口与实机验收范围见[使用说明的开发验证部分](sync-guide.md#开发验证)。保留协议、请求量、发布恢复及实际故障回归，不将人工界面预览或外部测试服务器的临时脚本作为自动回归。
