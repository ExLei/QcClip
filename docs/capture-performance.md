# 剪贴板文本合并性能评估

评估日期：2026-10-17。环境：Windows 11 使用 Release 测试程序。

当前优化前的实现存在随历史数量增长的延迟，主要来自候选查询遍历历史和重复读取格式。优化后，5 万条合成历史的常见复制入库中位数约 15–21 毫秒。真正修改约 6 MiB 多格式条目的中位数约 49 毫秒，仍保留与内容大小相关的工作。不能据此保证每次复制都没有延迟。

## 测量范围

- 计时范围为 `store_captured_clipboard` 调用到返回，包含连接与结构校验、候选查找、合并、事务提交和同步清理。
- 不包含操作系统剪贴板捕获、通知和界面首帧渲染；样本未指定来源程序路径，因此未覆盖图标提取成本。
- 各临时库起始包含 1 千、1 万、5 万条历史，准备数据和构造输入不计时；每个场景预热 5 次。优化前各场景记录 30 次，最终复测记录 50 次。
- 普通历史由带唯一编号、约 512 字符的 UTF-16 文本构成。25 格式样本包含纯文本、HTML 和 23 个私有格式；小内容约 3 KiB，大内容为 5.75 MiB 可压缩字节，低压缩率样本为 2.875 MiB 确定性伪随机字节。
- 64 KiB 文本指约 64 KiB 的 ASCII 字符，Windows UTF-16 原始数据约 128 KiB。
- 所有写入、索引构建均发生在临时库或真实数据库的副本；真实数据库只读访问。

在该副本首次构建两个索引约耗时 93 毫秒。索引在打开数据库时以 `IF NOT EXISTS` 安装，后续打开不重建，每次复制不执行索引构建。未修改表字段、历史记录或数据库版本；兼容的未来数据库不安装本版本索引。

## 执行路径与优化

| 操作 | 现在的执行范围 |
| --- | --- |
| 任意捕获 | 校验本次格式并计算本次原始字节哈希；工作量随本次数据大小增长 |
| 原始字节及格式状态完全重复 | 通过原始内容哈希定位条目，只比较格式摘要和元数据；更新历史次数、时间和位置，不读旧外部文件、不生成预览、不重建格式 |
| 同文但本次格式较少，例如 Excel 后复制 QQ | 用索引找候选，只读取文本校验所需的格式；若没有新变化，保留已有格式并只更新历史 |
| 同文且实际增加或改变格式 | 只加载命中的该条目全部格式，合并一次、生成预览一次；复用已校验且字节未变的外部文件，不重新压缩和落盘 |
| 外部格式清理 | 只有旧文件不再由合并后条目引用时才打开清理连接，仍检查其他条目引用 |
| 普通历史列表刷新 | 查询单条记录并增量更新；同位置且展示数据未变时保留自适应高度缓存 |
| 收藏页刷新 | 只有实际改变格式时才触发原有完整刷新，完全重复不会触发 |

文本候选索引只存前 128 个 Unicode 字符，避免将所有长预览完整重复存入索引。候选仍校验完整原文，前缀碰撞不会误合并。旧版原生文本哈希匹配也增加专用索引。删除了文本判等时对全部格式重复生成预览的操作，并复用已计算的合并哈希。格式顺序稳定保留，避免来源应用仅改变格式枚举顺序就重写格式。

## 保留的成本和限制

- 数据库连接和结构校验本身中位数约 9 毫秒，是此前已有的固定成本。它仍会核验多个表、字段和约束，不是扫描全部历史内容；本轮没有更改兼容性校验机制。
- 真正改变格式时仍会读取该条目的完整原始数据、计算内容哈希并重建该条目的格式记录。大条目仍可能出现几十毫秒开销，不能声称按单个改变的格式完成所有工作。
- 缺失预览的旧记录仍走完整文本回退。32 条缺失预览时新短文本中位数约 19 毫秒；若大量旧记录缺失预览，或大量长文本共享相同 128 字符前缀，工作量仍会随候选数量增长。
- 默认普通历史页使用增量刷新；启用保留天数/数量策略、搜索筛选或在收藏页实际修改格式时，已有路径仍可能重新读取排序 ID、统计或刷新列表。此次未测界面事件到首帧的耗时。
- 复测仍有偶发尾部高值：开启合并的个别样本达到约 935 毫秒，关闭合并的近似对照也达到约 947 毫秒。此前一轮还出现秒级异常，已保留原始结果；尚未定位这些高值的系统或 I/O 原因，不能将全部高值归因于合并，也不能宣称尾延迟已经解决。
- 临时库中的关闭合并对照通过未来版本兼容保护实现，用于观察连接、哈希与提交的固定成本；它不执行同文格式更新，与启用合并的写入语义不同，不代表精确的旧版本性能。
- 测试使用预热后的本机环境，未覆盖冷启动磁盘、长期并发读写或其他硬件，未量化峰值内存。

## 验证与复现

相关功能检查：捕获模块 46 项、数据库初始化与索引 10 项、兼容性 11 项通过。扩大回归检查有 538 项通过、2 项忽略，另跳过此前已在原始代码确认的 6 项失败用例：收藏排序/置顶相关 3 项、历史排序/置顶相关 2 项、侧栏布局边界 1 项。

手动基准默认忽略，不进入日常测试耗时。测试额外验证了查询计划使用索引、仅改变枚举顺序和重复纯文本不重写格式、修改 HTML 不重写已有外部格式，以及已有数据库补索引和未来数据库不被改写。
